Let Claude Code sessions in different Claude accounts message each other

With claude-multi-desktop, every Claude Desktop account on your Mac shares one Claude Code setup. Sessions in one account can therefore see the sessions in another account and send them messages.

Why it works

Claude Desktop keeps each account in its own folder, but the Claude Code sessions it starts all use ~/.claude. That folder holds your skills, CLAUDE.md, memory and settings, and also the list of Claude Code sessions running on this Mac. Because every account writes to the same list, a session in one account finds sessions in the others, and Claude Code's ListAgents and SendMessage tools can reach them.

Tools that give every account its own Claude Code folder keep accounts apart on purpose. That is the right choice when accounts must never meet, and this tool is for when you want them to work together.

Set it up

git clone https://github.com/jackson-cmd/claude-multi-desktop.git
cd claude-multi-desktop
./claude-multi-desktop add Personal   # then open it and sign in
./claude-multi-desktop add Main --default

Open a session in the Code tab of each window. This was tested with Claude Code 2.1 inside Claude Desktop.

See every session

$ ./claude-multi-desktop peers
ACCOUNT        STATUS SESSION
Personal       idle   trip planning
default        busy   paper review

The same list is what a session sees when it calls ListAgents.

Send work across accounts

In any session, ask in plain words:

  • “List the other Claude sessions running on this Mac.”
  • “Send the trip planning session in my Personal account this list and ask it to pick three hotels.”
  • “When it replies, summarise what it chose.”

The message arrives in the other account's session as a new turn, and that session answers with its own account, its own chat history and the same shared skills. You can draft in one account and have another account review it, or hand a long task to a session that is free.

Things to keep in mind

  • Everything in ~/.claude is shared, including memory written by any account.
  • peers reads Claude Code's local session list, so a future Claude release may change what it can show.
  • Each account remains subject to Anthropic's terms.
